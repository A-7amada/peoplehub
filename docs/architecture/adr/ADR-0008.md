# ADR-0008: REST and mobile API

**Status:** Accepted (2026-11-25 22:50, Ahmed). Implementation status is tracked in BLUEPRINT.md.

## Context
Only api/device for attendance devices.

## Decision
Define API conventions (versioned /api/v1, error shape, paging, tenant and permission binding) and ship two examples. The full mobile API is Phase 2.

## Alternatives considered
Full API now (delays the foundation). No conventions (rework later).

## Consequences
Small now.

## Design patterns used
Pattern: Anti-corruption layer / DTO boundary.
