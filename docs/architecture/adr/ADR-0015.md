# ADR-0015: decimal(18,2) migration timing

**Status:** Accepted (2026-11-25 22:50, Ahmed). Implementation status is tracked in BLUEPRINT.md.

## Context
Entities declare decimal but money is stored as double through a global EF conversion.

## Decision
Do it before tenancy. Steps: encrypted backup, restore of that same backup into Postgres in GitHub Actions with counts and totals checked, migration in a quiet window, before and after totals compared, rollback by restoring the backup.

## Alternatives considered
After tenancy (bigger migrations). Without a restore drill (not acceptable for payroll).

## Consequences
Medium.

## Design patterns used
Pattern: Value Object (Money) is a possible follow-up.
