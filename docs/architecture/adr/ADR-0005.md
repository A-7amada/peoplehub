# ADR-0005: Module boundaries and contracts

**Status:** Accepted (2026-11-25 22:50, Ahmed). Implementation status is tracked in BLUEPRINT.md.

## Context
Modules are folder and name groupings inside shared assemblies. Any service reads any table.

## Decision
Each module owns a folder and namespace in each layer and exposes a small public contract (interfaces and DTOs). Architecture tests fail the build if a module touches another module's internals or tables. Applied module by module, starting with Employees, Leave and Payroll.

## Alternatives considered
One assembly per module (compiler-enforced, heavy). Leave as is (drifts).

## Consequences
Large but incremental. No money.

## Design patterns used
Patterns: Facade per module (public contract), Dependency Inversion, architecture tests as fitness functions.
